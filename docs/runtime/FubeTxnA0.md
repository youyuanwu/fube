# Fube transaction A0: private native kernels

**Status:** implemented, offline source-derived A0 kernels. This document records
the A0 boundary; [A1](FubeTxnA1.md) now supplies the public volatile integration.
Neither milestone establishes native interoperability or persisted support.
**Native source:** Service Fabric
`51a7703a1f83749a9234d3ceb4296d8622e42cca`.
**Validation:** deterministic Rust tests, not executions of a native binary.

## 1. Architecture and access boundary

The public [`fube-txn`](../../crates/libs/fube-txn/src/lib.rs) contracts are
unchanged. Concrete components live in private
[`kernel`](../../crates/libs/fube-txn/src/kernel.rs). A maintainer can exercise
them with crate-local tests. The later [A1 service owner](FubeTxnA1.md) exposes
supported integrated execution without exporting kernel internals.
The same lower engine/binder and native membership/role/quorum/epoch authority
remain the [design](FubeDataV2Design.md). A0 itself added no runtime adapter.

Lower admission/LSN, flush and quorum completion are separate finite test inputs
([processor.rs:172–226](../../crates/libs/fube-txn/src/kernel/processor.rs#L172-L226)).
The processor executes actual codecs/map/provider callbacks between them;
it is not a fake transaction manager that returns success. An established
bootstrap role/tail/version is an explicit offline input, not election control.
Registry metadata/stream and physical checkpoint I/O are opaque source-format
side-effect seams, not implemented hierarchy, disk or negotiation codecs.

## 2. Records and transaction identity

Supported logical types retain native values: begin1, operation2, end3,
barrier4, update-epoch5. Inherited sections each occupy a segment, with a
32-bit size including itself and independent unknown-field skipping.
Payloads are metadata, redo, undo; native count/length framing distinguishes
absent data, nonnull zero segments and empty segments. Native metadata has a
trailing 16-byte routing header; copy data has a leading 12-byte header.

The [59-byte begin fixture](../../crates/libs/fube-txn/src/kernel/record.rs)
is derived from native writer fields; it is **not** generated by a native
binary. Checked malformed framing/length/bool/quota/overflow rejection is an
A0 safe-input boundary, not a claim that native assertions return those errors.
Replication serializes before lower LSN assignment, and secondary metadata
overrides embedded LSN; copied records retain original LSN
([trace_tests.rs:1413–1460](../../crates/libs/fube-txn/src/kernel/trace_tests.rs#L1413-L1460)).

IDs use native 100-ns UTC clock units and a shared high-water lock: newer time
wins, otherwise previous+1. Replay advances to absolute signed ID. Negative
atomic recognition is not permission to execute atomic APIs. No UUID,
incarnation/request ID, digest, ordinal or fabricated transaction LSN is added.
Authority: [TransactionBase.cpp:78–128][ids], [native logical reader][codec] and
[writer:845–873][writer].

## 3. Decisions, visibility and failure

First write is cached. Second emits begin and operation; subsequent writes are
incremental and can interleave. Read-only commit emits nothing and keeps invalid
commit LSN; cached abort invokes original-context cleanup without an end.
Single commit is one flagged begin, multi commit is an end.
Admission mutates map even if later Apply/quorum fails.

Successful flush alone does not dispatch a transaction group: the native
parallel algorithm accumulates until a barrier. It publishes the dispatching
Apply fence before launching that group, but identifies the sampled barrier
version only after preceding processing completes. Independent transaction
groups run concurrently, preserving their own record order
([processor.rs:787–960](../../crates/libs/fube-txn/src/kernel/processor.rs#L787-L960),
[native dispatcher][dispatch]).
The A0 dispatcher profile uses explicit native barriers; the optional native
commits-as-barriers setting is not enabled by this private profile.

Operation Apply LSN differs from multi commit LSN. Primary Apply may precede
quorum; completion awaits Apply then replication and invokes Unlock regardless
of those results. Either failed accepted boundary becomes TransactionAborted.
Nonnull Apply capture replaces the original; null retains it. Unlock takes a
slot first and stops at its first failure, retaining later slots. The caller can
still return success while cleanup faults and notification is suppressed.
Secondary normal processing includes Unlock before the following group/barrier;
failed-flush immediate replay does not synthesize Unlock/notification
([processor.rs:960–1082](../../crates/libs/fube-txn/src/kernel/processor.rs#L960-L1082),
[native completion][completion]).

Processor faults latch the first service status, close new lower write admission
and notify once, while accepted work continues. Recovery-role error probes
surface failure without ordinary processor fault reporting; checkpoint faults
have their distinct native reporting path. These probes do not implement open/
persisted recovery. Cached-abort StateManager cleanup faults separately and the
successful wrapper discards its inner status, allowing worker Aborted.

Retry is only native no-write-quorum, reconfiguration-pending, queue-full and
service-too-busy. Timeout/cancellation is checked after those failures, not
successful accepted work; elapsed equality does not time out. Source quirks
remain: 32-ms retry setter no-op, atomic retry leaves Committing, expired manager
can leave Committing/Aborting, dispose ignores snapshot-unregister status,
inclusive upper retaining sets and last stable end retained in the map.

The point fixture uses per-key transaction locks/captures and versions, not a
whole-root transaction swap. Repeatable conflicts wait; snapshot reads use a
cached Apply-fenced VSN and may see eligible applied state before quorum/Unlock.
Own writes publish only after successful operation admission. Payload/read/fault
policy is fixture-specific, not TStore/Reliable Collections compatibility
([provider.rs:972–1155](../../crates/libs/fube-txn/src/kernel/provider.rs#L972-L1155)).
Primary stability uses successful barrier's own LSN after Apply/quorum;
secondary uses advertised stable LSN after Apply. Neither is actual log tail.

## 4. Checkpoint and copy

Checkpoint waits dispatch and begin-flush status; a successful flush then
inherits prior service error before any Prepare. Prepare is sequential after
local metadata capture; Perform and Complete start all provider callbacks and
await all, preserving first array-order error and peer effects. Local Perform/
Complete follow providers. EndCheckpoint/flush precedes Complete; successful
Complete precedes CompleteCheckpoint/flush. Physical void flush completion does
not invent checked record-flush/durability guarantees.

First copy signals phase1 after Perform; Complete waits copy drain and actual
tail equality. Interruption cancels instead of reporting completed installation.
Aggregate copy always has a registry stream, then descending-name active provider
streams; absent individual stream is valid. Some(empty) is header-only data,
not EOS. Registry metadata starts only applicable initialized/resurrected
providers; Set preserves global signed number and no aggregate token; End is
local-first and only for actually begun providers. Interrupted EOS/error after
Begin does not call End. Dropping observers does not abandon owned ACK/cursor/
End continuation. Explicit Dispose remains separate from EOS and observer drop
([callback_tests.rs:804–1408](../../crates/libs/fube-txn/src/kernel/callback_tests.rs#L804-L1408),
[native copy caller][copycaller]).

## 5. Maintainer validation

Use the existing workspace toolchain; no native build or cluster is required:

```sh
CARGO_BUILD_JOBS=1 cargo test --locked -p fube-txn -- --test-threads=1
CARGO_BUILD_JOBS=1 cargo clippy --locked -p fube-txn --all-targets -- -D warnings
cargo fmt --all -- --check
CARGO_BUILD_JOBS=1 RUSTDOCFLAGS='-D warnings' cargo doc --locked -p fube-txn --no-deps
CARGO_BUILD_JOBS=1 RUSTDOCFLAGS='-D warnings' cargo doc --locked -p fube-txn --no-deps --document-private-items
```

The suite has 125 deterministic kernel tests at the final local checkpoint.
T01–T21 and S/V/W/K/C source projections are named in trace/callback and adjacent
tests. They assert caller versus canonical log/map, provider versions, retained
captures, faults, ACKs and intermediate partial orders. Compile-only SDK/internal
witnesses remain signature checks and contribute **zero behavioral tests**.
Neither equal final maps nor success from a fake engine is acceptance evidence.

## 6. Unsupported and qualification boundaries

Atomic/atomic-redo execution, backup, false progress, managed named/copy formats,
physical codecs, persisted recovery/restore and full registry creation/hierarchy
are unsupported. Negative IDs/redo-only codec recognition and the atomic state
hook do not enable those APIs; rejected execution never substitutes record kinds.
Ordinary stale/false-progress provider state is excluded; only DelayDelete takes
the supported skip/closed paths.
Active registration is distinct from retaining a deleted provider object.
Already-deleted providers reject before first-cache/logged admission; a valid
late DelayDelete Apply can still skip. Replay preflights native named routing
before append even for covered-prefix records; codec ID advancement remains
separate from this execution-support gate.

At the A0 checkpoint, lower lifecycle/engine stream/ACK pumps and native copy
negotiation were absent; [A1](FubeTxnA1.md) now implements the volatile paths,
physical codecs and primary registry/hierarchy. Full collections, deployment qualification, mixed-native replicas,
native binary format provenance and persisted manifests remain unclaimed.
This source pin is not deployed-binary evidence. Private logs/provider captures
are test-bounded, not a production memory-quota/recovery/lifecycle guarantee.
